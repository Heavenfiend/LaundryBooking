# LaundryBooking

Проект по «Практикуму IT-разработки».

Сервис бронирования времени на стиральные машины: участники общей «стиралки» (общежитие, подъезд,
коворкинг) записываются на часовые слоты, а администраторы управляют участниками и синхронизируют
расписание с Excel-таблицей.

**Стек:** React + TypeScript (Vite) · FastAPI · PostgreSQL · Docker Compose.

## Возможности

- **Аккаунты** — регистрация и вход по логину и паролю.
- **Стиралки** — создание, поиск по короткому ID, приглашение ссылкой или QR-кодом.
- **Заявки на вступление** — человек подаёт заявку, администратор одобряет или отклоняет.
- **Роли** — создатель, администраторы, участники (см. таблицу ниже).
- **Расписание** — сетка «дни × часы» за неделю до и три недели после текущего дня; запись и отмена
  в один клик.
- **Экспорт в `.xlsx`** — доступен любому участнику; таблица выглядит так же, как расписание на сайте.
- **Импорт из `.xlsx`** — доступен администраторам; с предпросмотром и ручным разбором конфликтов.
- **Светлая и тёмная тема** — переключается автоматически по настройке системы.

| Экспорт расписания в `.xlsx`                          |    ✓     |   ✓   |     ✓     |
| Одобрять и отклонять заявки, удалять участников       |          |   ✓   |     ✓     |
| Удалять чужие записи                                  |          |   ✓   |     ✓     |
| Менять название, описание, лимит участников           |          |   ✓   |     ✓     |
| Импорт из `.xlsx`                                     |          |   ✓   |     ✓     |
| Назначать и снимать администраторов                   |          |       |     ✓     |
| Удалять администраторов, удалять стиралку             |          |       |     ✓     |

## Быстрый старт

Нужен только [Docker](https://docs.docker.com/get-docker/) с Docker Compose (Docker Desktop
на Windows/macOS должен быть запущен).

```bash
git clone https://github.com/SpaghettiRebel/LaundryBooking.git
```

```bash
cd LaundryBooking
```

```bash
docker compose up --build
```

После сборки:

- сайт — http://localhost:8080
- Swagger (документация API) — http://localhost:8000/docs

Таблицы в базе создаются автоматически при первом старте. Первая сборка занимает несколько минут
(скачиваются образы и зависимости), следующие — секунды.

### Управление

| Команда                         | Что делает                                   |
| ------------------------------- | -------------------------------------------- |
| `docker compose up --build -d`  | собрать и запустить в фоне                   |
| `docker compose logs -f backend`| логи бэкенда                                 |
| `docker compose down`           | остановить (данные сохраняются)              |
| `docker compose down -v`        | остановить и **стереть базу данных**         |

### Настройки

Необязательные переменные окружения — можно положить в файл `.env` рядом с `docker-compose.yml`:

| Переменная     | По умолчанию           | Назначение                                        |
| -------------- | ---------------------- | ------------------------------------------------- |
| `SECRET_KEY`   | `dev-secret-change-me` | ключ подписи JWT; **обязательно сменить** вне локального запуска |
| `APP_TIMEZONE` | `Europe/Moscow`        | часовой пояс, в котором живут все расписания      |

Порты `8080` (сайт) и `8000` (API) меняются в секции `ports` файла `docker-compose.yml`.

### Локальная разработка без пересборки образов

```bash
docker compose up -d db backend
```

```bash
cd frontend && npm install && npm run dev
```

Vite поднимет фронт на http://localhost:5173 с горячей перезагрузкой и будет проксировать `/api`
на бэкенд `localhost:8000`.

## Как пользоваться

1. Зарегистрируйтесь и создайте стиралку — вы станете её создателем.
2. На вкладке «Поделиться» скопируйте ссылку или покажите QR-код. Стиралку также можно найти
   по ID на главной странице.
3. Приглашённый подаёт заявку, вы одобряете её на вкладке «Участники».
4. На вкладке «Расписание» нажмите на свободную ячейку, чтобы занять час. Нажмите на свою запись,
   чтобы отменить её.

Правила бронирования:

- на одно и то же время может быть только одна запись;
- записаться можно только на будущее время и не дальше чем на 21 день вперёд;
- участник удаляет только свои будущие записи, администратор — любые;
- при выходе или удалении участника его будущие записи удаляются.

**Лимит участников** задаётся при создании стиралки: заявку нельзя одобрить, пока мест нет,
а сам лимит нельзя опустить ниже текущего числа участников.

## Работа с Excel

Таблица повторяет расписание на сайте: столбец — один день, строка — один час, в ячейке — кто записан.

| Время | 13.11.2026 | 14.11.2026 | 15.11.2026 |
| ----- | ---------- | ---------- | ---------- |
| 09:00 |            |            | slava      |
| 10:00 |            |            | slava      |
| 11:00 | slava      |            | Петя       |

- **Первая строка** — даты. Понимаются настоящие даты Excel, текст `13.11.2026` и вид как на сайте,
  `пт 13.11` (год берётся ближайший к текущей дате).
- **Первый столбец** — время начала часа: `09:00`. Можно указать диапазон `09:00–10:30`, тогда
  запись будет этой длины.
- **Ячейка** — имя или логин участника. Имя, которого нет среди участников, становится записью
  на «гостя».

Типичный цикл синхронизации: **экспорт → правки в Excel → импорт того же файла**.

Что происходит при импорте:

| Ситуация                                               | Результат                                              |
| ------------------------------------------------------ | ------------------------------------------------------ |
| Ячейка заполнена, на сайте время свободно              | новая запись                                           |
| Ячейка совпадает с записью на сайте                    | без изменений                                          |
| Ячейка заполнена, на сайте время занято другим         | **конфликт** — решается вручную                        |
| Ячейка пустая, на сайте запись есть                    | запись предлагается удалить галочкой; по умолчанию остаётся |
| Дата столбца вне окна расписания                       | ячейки пропускаются, их число показывается             |
| Дату или время не удалось распознать                   | строка помечается ошибкой, её можно исправить на месте |

Конфликт администратор разбирает одним из трёх способов: поправить дату или время в строке,
пропустить строку (останется запись сайта) или отметить мешающую запись сайта на удаление
(останется запись из файла). Пока остаётся хоть один конфликт или ошибка, импорт не применяется.

## Тесты

Автотесты бэкенда написаны на pytest и запускаются в Docker одной командой:

```bash
docker compose run --rm --build tests
```

Тесты работают в отдельной базе `laundry_test` на том же сервере PostgreSQL — она создаётся
автоматически, рабочие данные не затрагиваются. Запущенный сервис останавливать не нужно.

| Файл                 | Что проверяет                                                              |
| -------------------- | -------------------------------------------------------------------------- |
| `test_auth.py`       | регистрация, вход, валидация, доступ без токена                            |
| `test_laundries.py`  | создание и поиск, заявки, лимит участников, роли, удаление участников и стиралки |
| `test_bookings.py`   | окно расписания, запись и отмена, пересечения, права на удаление           |
| `test_excel.py`      | экспорт сеткой, импорт: новые записи, гости, конфликты и три способа их разбора, пустые ячейки |
| `test_units.py`      | поиск пересечений интервалов, разбор дат и времени из таблицы              |

Запустить часть тестов: `docker compose run --rm tests pytest tests/test_excel.py -k conflict -v`.

Тесты API ходят в приложение через `TestClient` и настоящий PostgreSQL, а не через заглушки:
блокировки и каскадные удаления проверяются на той же СУБД, что и в работе. Каждый тест создаёт
своих пользователей и свою стиралку, поэтому тесты не зависят друг от друга и от порядка запуска.

## Архитектура

```
┌──────────┐      ┌────────────────────────────┐      ┌──────────────────┐      ┌────────────┐
│ Браузер  │ ───► │ frontend (nginx :80)       │ ───► │ backend (FastAPI │ ───► │ PostgreSQL │
│          │ :8080│  · отдаёт собранный React  │ /api │  монолит, :8000) │      │    :5432   │
└──────────┘      │  · проксирует /api         │      └──────────────────┘      └────────────┘
                  └────────────────────────────┘
```

Три контейнера в одной сети Docker Compose:

- **db** — PostgreSQL 16, данные лежат в именованном томе `pgdata`.
- **backend** — монолит на FastAPI: аутентификация, бизнес-правила, работа с Excel. Запускается
  после того, как база прошла healthcheck.
- **tests** — четвёртый, необязательный сервис (профиль `test`): тот же образ бэкенда с pytest,
  поднимается только по `docker compose run`.
- **frontend** — многоэтапная сборка: Node собирает статику, nginx её раздаёт и проксирует `/api`
  на бэкенд. Благодаря этому фронт и API живут на одном origin и CORS не нужен.

Бэкенд разделён на слои:

| Слой            | Файлы                         | Ответственность                                    |
| --------------- | ----------------------------- | -------------------------------------------------- |
| HTTP            | `routers/*.py`                | маршруты, коды ответов                             |
| Доступ          | `deps.py`                     | текущий пользователь, проверка роли в стиралке     |
| Контракты       | `schemas.py`                  | валидация входа и форма ответа (Pydantic)          |
| Бизнес-правила  | `logic.py`, `routers/excel.py`| пересечения записей, разбор и сверка таблицы       |
| Данные          | `models.py`, `db.py`          | ORM-модели и сессии SQLAlchemy                     |

## Модель данных

```
User ──< Membership >── Laundry ──< Booking >── User (необязательно)
```

| Таблица       | Ключевые поля                                                        |
| ------------- | -------------------------------------------------------------------- |
| `users`       | `username` (уникальный), `display_name`, `password_hash`             |
| `laundries`   | `code` (публичный ID), `name`, `description`, `capacity` (лимит участников) |
| `memberships` | `laundry_id`, `user_id`, `role` (owner / admin / member), `status` (pending / active) |
| `bookings`    | `laundry_id`, `user_id` или `guest_name`, `start_at`, `end_at`, `note` |

- Заявка на вступление — это `Membership` со статусом `pending`; одобрение меняет статус, отдельной
  таблицы заявок нет.
- У записи заполнено либо `user_id`, либо `guest_name` — так импорт из Excel может завести запись
  на человека без аккаунта.
- Удаление стиралки каскадно удаляет её участников и записи на уровне внешних ключей.

## Технические решения

**Монолит вместо сервисов.** Предметная область маленькая и связная: бронь зависит от членства,
импорт — от броней. Один процесс и одна база дают транзакционную целостность без распределённых
согласований.

**Запись — это интервал, а не клетка.** В базе хранится `[start_at, end_at)`. Сетка по часам —
лишь представление: интерфейс создаёт часовые записи, а импорт может завести и `09:00–10:30`.
Проверка пересечений (`logic.py`) работает с произвольными интервалами.

**Защита от гонок.** Перед проверкой пересечений и вставкой бэкенд берёт блокировку строки стиралки
(`SELECT … FOR UPDATE`). Два одновременных запроса на один слот выполняются по очереди, и второй
получает `409`. Тот же приём защищает лимит участников при одновременном одобрении заявок.

**Местное время без часового пояса.** Стиралка — физическое место, поэтому время записи хранится
как «время на стене» (`timestamp without time zone`), а «сегодня» считается на сервере в поясе
`APP_TIMEZONE`. Фронт не преобразует время через пояс браузера, так что участник в другом
часовом поясе видит то же расписание, что и остальные.

**Окно расписания считает сервер.** Диапазон «−7 … +21 день» и текущий момент приходят в ответе API.
Клиент только рисует сетку, поэтому неверные часы на устройстве не ломают правила бронирования.

**Импорт в три шага: разбор → сверка → применение.**

1. Файл разворачивается из сетки в список строк «дата, начало, конец, участник».
2. Одна функция `evaluate` сверяет строки с базой и присваивает каждой статус
   (новая / без изменений / конфликт / ошибка). Она же вызывается при перепроверке после правок
   администратора и непосредственно перед записью — логика проверки не дублируется.
3. Применение идёт одной транзакцией под блокировкой стиралки и только если не осталось конфликтов
   и ошибок. Импорт либо выполняется целиком, либо не меняет ничего.

Сервер не хранит состояние незавершённого импорта: список строк и решения администратора живут
в браузере и отправляются целиком при каждой перепроверке.

**Идемпотентность импорта.** Повторная загрузка той же таблицы ничего не меняет: ячейка считается
уже существующей, если её время целиком покрыто записью того же человека.

**Удаление только с явного согласия.** Пустая ячейка сама по себе ничего не удаляет — такие записи
выводятся отдельным списком с галочками. Учитывается только время, которое в таблице есть: если
в файле нет какого-то дня или часа, записи на это время не затрагиваются.

**Аутентификация.** Пароли хешируются bcrypt, сессия — JWT (HS256, 14 дней) в заголовке
`Authorization`. Токен хранится в `localStorage`; при ответе `401` фронт сбрасывает его
и отправляет на страницу входа.

**Публичный ID стиралки.** Шесть символов из алфавита без похожих знаков (`0/O`, `1/I`) — удобно
диктовать и вводить вручную. Числовой первичный ключ наружу не выдаётся.

**Собственные диалоги вместо `confirm()` и `alert()`.** Встроенные браузеры и веб-вью нередко молча
блокируют нативные окна, из-за чего действие «не срабатывает». Подтверждения и уведомления
отрисовываются самим приложением.

**Минимум зависимостей на фронте.** React, React Router и генератор QR-кодов. Состояние — локальное
в компонентах, стили — один CSS-файл на переменных; UI-библиотек и менеджера состояния нет.

**Схема без миграций.** Таблицы создаются через `create_all` при старте — осознанное упрощение
для MVP (см. ограничения).

## API

Полное интерактивное описание — в Swagger: http://localhost:8000/docs. Все маршруты, кроме
регистрации и входа, требуют заголовок `Authorization: Bearer <token>`.

| Метод и путь                                    | Назначение                                | Доступ     |
| ----------------------------------------------- | ----------------------------------------- | ---------- |
| `POST /api/auth/register`, `/login`             | регистрация и вход                        | все        |
| `GET /api/auth/me`                              | текущий пользователь                      | вошедший   |
| `GET /api/laundries`                            | мои стиралки и заявки                     | вошедший   |
| `POST /api/laundries`                           | создать стиралку                          | вошедший   |
| `GET /api/laundries/{code}`                     | карточка стиралки (поиск по ID)           | вошедший   |
| `PATCH /api/laundries/{code}`                   | изменить название, описание, лимит        | админ      |
| `DELETE /api/laundries/{code}`                  | удалить стиралку                          | создатель  |
| `POST /api/laundries/{code}/join`               | подать заявку                             | вошедший   |
| `POST /api/laundries/{code}/leave`              | выйти или отозвать заявку                 | участник   |
| `GET /api/laundries/{code}/members`             | список участников и заявок                | участник   |
| `POST …/members/{user_id}/approve`              | одобрить заявку                           | админ      |
| `DELETE …/members/{user_id}`                    | отклонить заявку или удалить участника    | админ      |
| `PUT …/members/{user_id}/role`                  | назначить или снять администратора        | создатель  |
| `GET /api/laundries/{code}/bookings`            | расписание за окно                        | участник   |
| `POST /api/laundries/{code}/bookings`           | создать запись                            | участник   |
| `DELETE …/bookings/{id}`                        | удалить запись                            | свою / админ |
| `GET /api/laundries/{code}/export`              | скачать `.xlsx`                           | участник   |
| `POST /api/laundries/{code}/import/parse`       | загрузить `.xlsx`, получить предпросмотр  | админ      |
| `POST /api/laundries/{code}/import/apply`       | перепроверить (`dry_run`) или применить   | админ      |

## Ограничения MVP

- **Нет миграций базы.** При изменении моделей существующую базу нужно пересоздать
  (`docker compose down -v`) либо добавить Alembic.
- **Фронтенд автотестами не покрыт** — он проверялся вручную в браузере; тесты есть только
  у бэкенда.
- **Один часовой пояс на всю установку** — задаётся переменной `APP_TIMEZONE`.
- **Одна запись на время.** Несколько машин в одной стиралке не моделируются — для второй машины
  создаётся отдельная стиралка.
- **Комментарии к записям в таблицу не попадают:** в ячейке Excel хранится только имя.
- **Нет восстановления пароля и подтверждения почты.**
- **Развёртывание не настроено:** нет HTTPS, а значение `SECRET_KEY` по умолчанию годится только
  для локального запуска.
